# JPEG 2000 interoperability fixtures

Full DICOM container fixtures and their independent decoded baselines are in
[`dicom/`](dicom/README.md).

`fo_dicom_codecs_synthetic8_lossless.j2k` is a raw SOC-through-EOC codestream
generated by `fo-dicom.Codecs` 5.16.7 through its public `DicomTranscoder` API
in a separate .NET 10 process. The source dataset was synthetic and contained
one unsigned 8-bit `MONOCHROME2` frame, 67 columns by 65 rows. For each pixel
at `(x, y)`, its value was `(x * 31 + y * 73 + (x ^ y) * 7) & 255`.

The encoder used transfer syntax `1.2.840.10008.1.2.4.90` and its default
parameters. The codestream has five decomposition levels, 64x64 code blocks,
and eight quality layers. The DICOM container and any even-length fragment
padding were excluded from this fixture.

| Item | SHA-256 |
| --- | --- |
| Source pixels, row-major | `EBEFE59C1BFA9785D48ED1A1973978C6BE8CD6FC2B866BCF40218FFBC68C08D7` |
| Raw J2K codestream, 4431 bytes | `76FA637878E757DEA9225C1C363AE30994D398F1C1361DAEFC8A45F45090152C` |

The Java test compares decoded pixel bytes with the source pixel hash. Fixture
generation does not add a native dependency to the Java module.

## Reproducible lossy fixture

`fo_dicom_codecs_synthetic8_lossy.j2k` uses the same 67x65 unsigned 8-bit
`MONOCHROME2` source formula above. It was encoded in a separate .NET 10
process with `fo-dicom.Codecs` 5.16.7, transfer syntax
`1.2.840.10008.1.2.4.91`, and default encoder parameters. The uncompressed
frame produced by that decoder is
`fo_dicom_codecs_synthetic8_lossy_reference.raw`. The Java decoder's maximum
absolute sample difference from this native reference is at most 6.

| Item | SHA-256 |
| --- | --- |
| Raw J2K codestream, 260 bytes | `42CBC81A56B249B090BA0CCE560959FD8D94B12657B602DE7BD82270D5D060BB` |
| Native decoded reference, 4355 bytes | `643361D0D0C9D088DAB6942CC2783AA526C4E8CBAC020CD313A1C1DE0BE812C7` |

From the repository root, `dotnet run --project tools/fo-dicom-fixtures/jpeg2000 --
synthesize <source.dcm>` creates the source dataset, and `dotnet run --project
tools/fo-dicom-fixtures/jpeg2000 -- encode <source.dcm> <frame.j2k> 91 <reference.raw>`
reproduces the codestream and native reference. The helper is only an
interoperability tool; the Java codec has no native runtime dependency.

## Java marker variants checked by a foreign decoder

The five `java_synthetic_*.j2k` files are raw `.90` codestreams from
`Jpeg2000InteropGenerationTest`, which writes them to the module's `target`
directory. They use the same 67x65, unsigned 8-bit `MONOCHROME2` source formula
and no DICOM container or padding. All have 64x64 code blocks and five
decomposition levels. SOP/EPH, PPT, PPM, and RGN have one complete lossless
layer; POC has three layers (`128, 16, 0`), an RLCP packet sequence, and an
inserted POC marker selecting that sequence. RGN uses Maxshift 2.

| Variant | Bytes | SHA-256 |
| --- | ---: | --- |
| SOP/EPH | 4395 | `F0AE3440A3A4971C884FC6475AABEDAE03F5DDF180789CF281633FFF56CA59A1` |
| PPT | 4352 | `14D57FA246820479D4F8263F08B9FC1CE7A38856CCAA58B547E04AE6A2D86C65` |
| PPM | 4356 | `42E6F293ABA44287584B3B44E5C10E39FEDAFEB1A08CC81E880055A467DDC7BD` |
| RGN | 4412 | `33571A6F7C5106F372E1988956A91D4B4A28996B2C5F8063840E3399566177BC` |
| POC | 4382 | `8B776D885245F37A3E5F6AD41BD932E18B1D5AD260EE5080859EFB75FD8B2B8D` |

Each was independently decoded with `fo-dicom.Codecs` 5.16.7 using
`dotnet tools/fo-dicom-fixtures/jpeg2000/bin/Debug/net10.0/Jpeg2000Interop.dll verify
<source.dcm> <variant.j2k> 90`. Every variant returned 4355 pixels with
maximum error 0 and SHA-256
`EBEFE59C1BFA9785D48ED1A1973978C6BE8CD6FC2B866BCF40218FFBC68C08D7`.
`Jpeg2000MarkerInteropFixtureTest` also decodes these committed files in Java.

## Additional lossy acceptance fixture

`fo_dicom_codecs_unit8_lossy.j2k` is a 512x512, three-component, unsigned
8-bit lossy codestream; `fo_dicom_codecs_unit8_lossy_native.raw.gz` contains
the native decoder reference. Its original encoder settings and photometric
metadata are not recorded, so this fixture supplies a pixel-tolerance
regression only. The Java decoder has maximum error at most 6 and mean
absolute error below 1 against the reference.
